A Create and run your app

You already made one Flutter app when you installed Flutter. Tonight you make a new one, the same way, and this one you build yourself. Your code is saved in files on your laptop: no more DartPad.

1. Create the project. Open Android Studio → New Flutter Project (on the welcome screen, or File → New → New Flutter Project). Choose Flutter on the left and check the Flutter SDK path is the one you installed (C:\flutter or ~/development/flutter) → Next.

2. Name it. Project name: shopping_list (lowercase, with an underscore). Leave everything else as it is → Create. Android Studio opens your project.

3. Start your phone. Open Device Manager (the phone icon on the right edge, or Tools → Device Manager) and press ▶ next to your emulator. Wait until you see the phone's home screen. Using your own Android phone instead? Plug it in with USB debugging on, as in the install guide, and tap Allow on the phone.

4. Run the app. In the toolbar at the top, the device menu should show your emulator or phone. Press the green Run ▶ button. The first build of a new project is slow: it can take 5 to 10 minutes and needs the internet. That happens only the first time, so do not stop it. After that, changes appear in about a second.

The demo counter app on your emulator or phone: a + button and a number. Tap + and the number goes up.

Laptop too slow for the emulator, and no Android phone? Pick Chrome (web) in the device menu instead. Everything tonight works the same there.

B Warm-up: the Dart that Flutter uses

Flutter code is full of three Dart ideas you have not used much yet. Meet them first in plain Dart, on a bus you already know. No more DartPad: from today your code lives in files on your laptop, and it is saved.

🧠 Toolbox: three ideas

1. Classes. A class is a blueprint. Bus describes what every bus has (a route, a price, seats) and can do (book a seat). From one blueprint you make many objects: huye and musanze.

2. Named parameters. Bus(route: 'huye', price: 3000): each value has a label, so the order does not matter and the code reads like a sentence. required means you cannot forget it.

3. Functions as values. A function can be stored in a variable and called later. onPressed: () { ... } means "here is what to do when someone taps", not "do it now".

Create a new file called warmup.dart: in the Project panel, right-click the top shopping_list folder → New → Dart File → warmup. It sits next to pubspec.yaml, not inside lib. Type this and save. Then open the Terminal panel at the bottom and run dart run warmup.dart. The output appears in the terminal, not on the emulator.

class Bus {
  Bus({required this.route, required this.price});

  final String route;
  final int price;
  final seats = List<String?>.filled(6, null);

  void book(String name, int seat) {
    seats[seat - 1] = name;
  }

  int freeSeats() {
    return seats.where((s) => s == null).length;
  }
}

class Button {
  Button({required this.label, required this.onPressed});

  final String label;
  final void Function() onPressed;

  void tap() {
    print('[$label] was tapped');
    onPressed();
  }
}

void main() {
  // Objects made from a class
  final huye = Bus(route: 'huye', price: 3000);
  final musanze = Bus(price: 2500, route: 'musanze');
  huye.book('Keza', 3);
  print('${huye.route}: ${huye.freeSeats()} free');
  print('${musanze.route}: ${musanze.freeSeats()} free');

  // A function stored in a variable, called later
  final bookButton = Button(
    label: 'Book seat 1',
    onPressed: () {
      huye.book('Eric', 1);
      print('Eric booked. ${huye.freeSeats()} free on huye');
    },
  );
  print('Nothing happens until someone taps...');
  bookButton.tap();
}
huye: 5 free
musanze: 6 free
Nothing happens until someone taps...
[Book seat 1] was tapped
Eric booked. 4 free on huye
🔍 What just happened

Look at musanze: the price comes before the route, and it still works. That is the point of named parameters.

The onPressed code did not run when the button was made. It ran only when tap() called it. That is exactly how a Flutter button works: you give it a function, and Flutter calls it when the user taps.

Break it on purpose: change the first bus to Bus(route: 'huye') and run. Read the error.

Required named parameter 'price' must be provided.
✋ Your turn

Fix the error. Then make a second button, cancelButton, labelled 'Cancel seat 1'. When tapped, it empties seat 1 and prints how many seats are free. At the end of main, call cancelButton.tap(); after bookButton.tap();.

[Cancel seat 1] was tapped
5 free on huye

1 Hello, Flutter

🧰 Survival tips: read these before you type
  • Brackets come in pairs. Flutter code is widgets inside widgets, so you will have many ( ) and [ ]. Click next to a bracket and Android Studio highlights its partner.
  • End every widget's last line with a comma, then press Ctrl+Alt+L (Cmd+Option+L on a Mac): Reformat Code. Android Studio lines your code up neatly, and a missing bracket becomes easy to see.
  • Red wavy line? Hover over it to read the error. The Dart Analysis panel at the bottom lists them all, with line numbers.
  • Something looks wrong after a save? Do a hot restart. Still wrong? Stop the app ■ and press Run ▶ again.
  • An error you do not understand? Look it up in When something goes wrong at the end of this guide.

A light page with Shopping List at the top, and Nothing here yet in normal dark text in the middle. A small red DEBUG ribbon sits in the top-right corner.
🔍 What just happened

Your screen is now a tree of widgets, each one inside another:

MaterialApp └─ Scaffold the page: a top bar + a body ├─ AppBar the bar at the top │ └─ Text 'Shopping List' └─ Center puts its child in the middle └─ Text 'Nothing here yet'

See the warm-up in it? home:, appBar:, body:, child: and title: are all named parameters. Every widget is an object made from a class.

  • See every option: Ctrl+click (Cmd+click) on a widget name opens its code and lists everything it can take.

3 Your own widgets

Real apps are built from your own widget classes. Replace your code with this and hot restart one last time.

import 'package:flutter/material.dart';

void main() {
  runApp(const ShoppingApp());
}

class ShoppingApp extends StatelessWidget {
  const ShoppingApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      home: const HomeScreen(title: 'Shopping List'),
    );
  }
}

class HomeScreen extends StatelessWidget {
  const HomeScreen({super.key, required this.title});

  final String title;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(title)),
      body: const Center(
        child: Text('Nothing here yet'),
      ),
    );
  }
}
The same page, now with a light green tint, and the DEBUG ribbon is gone.
🔍 What just happened

ShoppingApp and HomeScreen are classes, just like Bus. extends StatelessWidget means "this is a widget that never changes by itself".

Every widget has a build method: Flutter calls it to ask "what should I draw?", and it returns a tree of widgets.

required this.title works like Bus(route: ...): HomeScreen(title: 'Shopping List') must be given a title, and the screen uses it in its AppBar.

Your screen now lives inside build methods, so from now on hot reload works: just save.

Words you will see in every Flutter file:

WordWhat it means
@override"I am writing my own version of a method Flutter expects", here build.
super.keyA name tag Flutter can use to tell widgets apart. Always include it; you will not need it yet.
BuildContext contextWhere this widget sits in the tree. Flutter hands it to build; you will use it in step 6.
const"This never changes", so Flutter can reuse it instead of building it again.
debugShowCheckedModeBanner: falseHides the red DEBUG ribbon.
ThemeData(colorSchemeSeed: ...)One colour, and Flutter makes a matching set of colours for the whole app.

4 Show a list

In the HomeScreen class, replace its build method (from @override down to the method's closing }) with this. Leave everything above it as it is.

  @override
  Widget build(BuildContext context) {
    final items = ['Milk', 'Bread', 'Rice'];

    return Scaffold(
      appBar: AppBar(title: Text(title)),
      body: ListView.builder(
        itemCount: items.length,
        itemBuilder: (context, index) {
          return ListTile(
            leading: const Icon(Icons.shopping_basket),
            title: Text(items[index]),
          );
        },
      ),
    );
  }
Three rows, Milk, Bread and Rice, each with a basket icon.
🔍 What just happened

items is an ordinary Dart list, exactly like the ones in your labs. The screen simply shows what is in it.

ListView.builder makes a scrolling list. You tell it how many rows there are (itemCount) and how to build one row (itemBuilder).

itemBuilder is a function given as a value, like onPressed in the warm-up. Flutter calls it once for each row, with that row's index: 0, 1, 2.

ListTile is a ready-made row with places for an icon (leading) and text (title).

5 Make it react

Right now nothing can change. Replace the whole HomeScreen class with these two classes:

class HomeScreen extends StatefulWidget {
  const HomeScreen({super.key, required this.title});

  final String title;

  @override
  State<HomeScreen> createState() => _HomeScreenState();
}

class _HomeScreenState extends State<HomeScreen> {
  final items = ['Milk', 'Bread', 'Rice'];

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(widget.title)),
      body: ListView.builder(
        itemCount: items.length,
        itemBuilder: (context, index) {
          return ListTile(
            leading: const Icon(Icons.shopping_basket),
            title: Text(items[index]),
          );
        },
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {
          setState(() {
            items.add('Item ${items.length + 1}');
          });
        },
        child: const Icon(Icons.add),
      ),
    );
  }
}
A + button at the bottom right. Each tap adds a row: Item 4, Item 5, Item 6…
🔍 What just happened

A StatefulWidget comes in two parts. The widget holds the settings that do not change (the title). Its State holds the data that does change (the items). Inside the State, you reach the settings with widget.title.

setState means: "I changed the data, please redraw the screen". Flutter then calls build again, and the new row appears.

The list moved out of build. Inside build it would be created fresh on every redraw, and your new items would be lost each time.

Three small new things: createState is how Flutter makes the State, once, when the screen first appears. The _ at the start of _HomeScreenState means "private": only this file can use it. And => is a short way to write a function that just returns one thing: () => _HomeScreenState() is the same as () { return _HomeScreenState(); }.

Experiment: remove setState(() { and its closing });, keeping only items.add(...). Hot restart and tap + three times. Then save the file (hot reload) without tapping.

Nothing happens when you tap (left). After the hot reload, three new items suddenly appear (right).

The data changed with every tap, but nobody told the screen. Put setState back.

✋ Your turn

Show how many items are on the list in the title, like Shopping List (5).

💡 Hint 1

Use interpolation in the AppBar title: '${widget.title} (${items.length})'.

6 Type your own items

From here you get less code. Read the goal, use the new pieces, and build it.

🎯 The goal
  • A text field and an Add button at the top of the page, with the list below them.
  • Typing an item and tapping Add puts it at the end of the list and empties the field.
  • Tapping Add with an empty field adds nothing and shows Type an item first at the bottom of the screen.
  • The + button is gone.

The new pieces. Add these inside _HomeScreenState, under items:

  final controller = TextEditingController();

  void addItem() {
    final text = controller.text.trim();
    if (text.isEmpty) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('Type an item first')),
      );
      return;
    }
    setState(() {
      items.add(text);
    });
    controller.clear();
  }

  @override
  void dispose() {
    controller.dispose();
    super.dispose();
  }

Now change the body so the text field and the button sit above the list, and remove the floatingActionButton. This is the tree you are building:

Scaffold ├─ AppBar └─ Column body: one thing under another ├─ Padding some space around the input row │ └─ Row side by side │ ├─ Expanded the field takes all the free width │ │ └─ TextField │ ├─ SizedBox a small gap │ └─ FilledButton 'Add' └─ Expanded the list takes the space that is left └─ ListView.builder your list from step 5, unchanged

Build it from the outside in: first the Column with your list inside it, save and check, then the input row.

On the emulator, click the field and type with your laptop keyboard. A small keyboard bar may float over the list while you type: it disappears when you press Enter or tap elsewhere.

💡 Hint 1

The outline of the body:

body: Column(
  children: [
    Padding(
      padding: const EdgeInsets.all(12),
      child: Row(
        children: [
          // the field, the gap and the button
        ],
      ),
    ),
    Expanded(
      child: ListView.builder(
        // your list from step 5
      ),
    ),
  ],
),
💡 Hint 2

In the Row: Expanded(child: TextField(controller: controller, decoration: const InputDecoration(hintText: 'Add an item'))), then const SizedBox(width: 12), then FilledButton(onPressed: addItem, child: const Text('Add')). Note onPressed: addItem with no brackets: you give the function, you do not call it.

Type Eggs, tap Add: Eggs appears at the bottom and the field is empty. Tap Add with nothing typed: Type an item first appears at the bottom of the screen.
🔍 What just happened

A TextEditingController holds what is typed in the field. controller.text reads it and controller.clear() empties it.

The empty-field check is a rule that refuses, like in your labs: check first and return early, so nothing is added.

dispose runs when the screen closes, and frees the controller.

🆘 Classic trap

Vertical viewport was given unbounded height, and the list disappears: your ListView is inside a Column without Expanded. A Column lets its children be as tall as they like, and a list wants infinite height. Wrap the list in Expanded(child: ...), which means "take the space that is left". Quick way: cursor on ListView → Alt+Enter → Wrap with widget… → type Expanded.

An InputDecorator, which is typically created by a TextField, cannot have an unbounded width: the same problem sideways. A TextField inside a Row needs Expanded around it too.

8 Mark as bought

🎯 The goal
  • Tapping an item marks it as bought: its name is crossed out and its icon becomes a tick. Tapping it again un-marks it.
  • The title shows how many items are left: Shopping List (2 left).
  • A button in the top bar removes all the bought items at once.

A text is not enough any more: each item now has a name and a bought status. Make a class for it, under the import line and above ShoppingApp:

class Item {
  Item(this.name);

  final String name;
  bool bought = false;
}

Then change items to [Item('Milk'), Item('Bread'), Item('Rice')] and fix everything that breaks. The red lines show you where. When there are no red lines left, do a hot restart, not just a save (the trap below explains why). Then do the goal one bullet at a time, and check each one before the next.

💡 Hint 1

At the top of itemBuilder, pick out the row's item: final item = items[index];. Then show item.name instead of items[index]. In addItem, add Item(text) instead of text.

💡 Hint 2

ListTile has an onTap. Inside setState, flip the status: item.bought = !item.bought;. Cross the text out with style: TextStyle(decoration: item.bought ? TextDecoration.lineThrough : null). For the icon: Icon(item.bought ? Icons.check_circle : Icons.shopping_basket).

💡 Hint 3

Items left: items.where((item) => !item.bought).length. The top bar button goes in AppBar(actions: [ ... ]), for example an IconButton with Icons.cleaning_services_outlined. items.removeWhere((item) => item.bought) removes the bought ones.

🆘 Classic trap

Invalid constant value on your icon or text: it still has const in front, but now it depends on item.bought, which changes. Something that changes cannot be constant. Remove that const.

🆘 Classic trap

A red screen saying type 'List<String>' is not a subtype of type 'List<Item>' right after you save: hot reload keeps the app's data, and the data it kept is the old list of texts, not your new list of Items. Do a hot restart: the app starts again and builds the new list. Whenever you change what kind of data you store, hot restart.

Tap Milk: it is crossed out and the title says (2 left). Tap it again: back to (3 left). Mark Rice, tap the top bar button: Rice is gone.
🔍 What just happened

Item is a model: a class that describes your data, separate from the widgets that show it. Every app you build will have models: a transaction, a candidate, a patient, a product.
